# 踩坑记

7 个只有真正跑起来才会遇到的问题。每条都附了现象、原因、修法。

---

## 1. 模型把 `null` 当成回答发出来

**现象**：用户说「提醒我喝水」，机器人回了一个 `null`。

**原因**：工具调用那一轮，模型返回的 `message.content` 是 `null`（它只想调工具，不想说话）。
如果原样把这条消息回填给下一轮，模型看到自己上一句是 `null`，就继续吐 `null`。

**修法**：回填前瘦身，并把最终答案做一次清洗。

```python
def _as_assistant(message):
    clean = {"role": "assistant", "content": message.get("content") or ""}
    if message.get("tool_calls"):
        clean["tool_calls"] = message["tool_calls"]
    return clean
```

```python
_EMPTY_WORDS = {"", "null", "none", "nil", "undefined"}


def final_text(content, tool_outputs):
    if (content or "").strip().lower() not in _EMPTY_WORDS:
        return content.strip()
    return tool_outputs[-1] if tool_outputs else "我没想出怎么回"
```

关键点：**用工具自己的返回值兜底**。`set_reminder` 返回的「记住了：xx 提醒你喝水」
本来就是给人看的，模型哑火时直接用它，用户仍然得到正确信息。

## 2. 「我这边拿不到当前时间」

**现象**：说「一分钟后提醒我」，机器人答「我拿不到当前时间，你给我个具体时间点」。

**原因**：模型不知道今天是几号。LLM 没有时钟。

**修法**：两处都做，缺一不可。

```python
# ① 每次请求把当前时间拼进 system prompt（治本，不额外多一轮）
now = datetime.now(ZoneInfo(settings.bot_timezone))
messages = [{"role": "system", "content": settings.prompt(now)}]


# ② 再给一个工具，长对话里时间漂移时能刷新
async def get_current_time() -> str:
    return f"现在是 {now:%Y-%m-%d %H:%M} 周{weekday}"
```

## 3. 提醒时间差 8 小时

**现象**：设定 11:44，通知里写「你在 03:44 设的」。

**原因**：`due.astimezone()` **不带参数 = 系统时区**，而容器默认是 UTC。

```python
due.astimezone()  # ❌ 容器里是 UTC
due.astimezone(ZoneInfo("Asia/Shanghai"))  # ✅
```

**教训**：容器时区和你本机不一样，所有时间转换都要显式指定时区。
顺带在 compose 里加 `TZ` 让日志时间戳也对。

## 4. 图片链接被贴进正文

**现象**：机器人回复里出现一长串 `![图](https://...token=...)`。

**原因**：工具的返回值里带了 URL，模型就照着念了一遍。

**修法**：URL 只走"发图"通道，不进返回值。

```python
context.add_image(url)  # 给发送层
return "图片已生成，正在发给你。"  # 给模型看
```

## 5. 微信发不出图片

**现象**：QQ 能发图，微信只收到文字。

**原因**：**微信图片消息不接受外链**，只认自己素材库里的 `media_id`。

**修法**：三步。

```
下载图片 → POST /cgi-bin/media/upload 换 media_id → 发 msgtype=image
```

失败就退回文字链接，至少用户能点开看。

## 6. `.env` 里的键重复了，改了不生效

**现象**：改了 `IMAGE_API_KEY` 却还是报错。

**原因**：之前用 `echo >>` 追加了多次，同一个 key 在两行里，**后者覆盖前者**。
你改的是上面那行，生效的是下面那行。

**排查**：

```bash
grep -oE "^[A-Z_]+=" .env | sort | uniq -d   # 输出重复的键名
```

**去重（保留最后一次）**：

```bash
tac .env | awk -F= '/^[A-Z_]+=/ { if (seen[$1]++) next } { print }' | tac > .env.new
mv .env.new .env
```

**习惯**：改配置用 `sed -i 's|^KEY=.*|KEY=新值|' .env`，不要用 `echo >>`。

## 7. 日志被公网扫描器刷屏

**现象**：80 端口暴露后，日志里全是 `GET / 404`、`HEAD /`。

**原因**：任何开放 80 端口的机器都会被扫描，这正常，但会把业务日志冲掉。

**修法**：关掉 uvicorn 的 access log，只留应用自己的日志。

```python
uvicorn.Config(app, ..., access_log=False)
```

因为业务侧已经打了 `收到微信消息 [xxxx] 你好`，排查时看那行就够。

## 8. 搜索「搜到了」但「搜得不对」

**现象**：问「今天有什么科技新闻」，机器人说「搜到的都是综合新闻和金融，没找到科技新闻」。

**原因**：模型把用户的口语原句**原样**丢给了搜索引擎。

```
用户：今天有什么科技新闻
工具：search("今天有什么科技新闻")     ← 搜索引擎不吃问句
```

搜索引擎匹配的是关键词，问句里的「今天」「有什么」都是噪音。

**修法**：三处一起调。

```python
# ① 工具描述里给示范，直接教它怎么改写
"query 必须是关键词组合，不要把用户的口语原句丢进来：
 用户问「今天有什么科技新闻」，应该搜「科技新闻 2026年11月」"

# ② 加 freshness 参数，让模型判断时效
"freshness": {"enum": ["noLimit", "oneDay", "oneWeek", "oneMonth"]}

# ③ 条数和摘要都给足
MAX_RESULTS = 8        # 4 太少，口语问题命中率本来就低
SNIPPET_CHARS = 500    # 300 会砍掉新闻的关键信息
```

改完后同一个问题，命中从「综合新闻」变成当天的乌镇峰会、AI 岗位薪资报告。

**教训**：工具的参数设计**本身就是提示词**。schema 里写「query: 搜索关键词」不够，
要写清「什么样的输入是好的」，模型才会照着做。

## 附：协议差异速查

| | QQ | 微信 |
|---|---|---|
| 连接方式 | WebSocket 长连接（出站） | HTTP 回调（入站，要 80/443） |
| 需要域名 | 否 | 建议有，IP 也行 |
| 回复时限 | 5 分钟 / 5 条 | **5 秒 / 1 条** |
| 主动消息 | 需申请权限，有配额 | 客服消息，48 小时内 |
| 发图 | 给 URL 即可 | 必须先上传换 media_id |
| 消息格式 | JSON | XML |
| 会重发吗 | 不会 | 会（5 秒超时重发 3 次，需按 MsgId 去重） |
