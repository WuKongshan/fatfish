# 网页桌宠（DSH Web + dsh-pet）

网页桌宠由独立的 DSH Web 容器提供，使用 dsh-pet 的原版网页插件。Fatfish 容器仍负责 QQ、微信和提醒；Caddy 在前面接收网页 HTTPS 请求，并把 `/wechat` 转回 Fatfish。

## 首次部署

服务器 `.env` 需要包含：

```dotenv
DEEPSEEK_API_KEY=你的DeepSeek_API_Key
PUBLIC_IP=43.138.189.204
```

然后在项目目录构建并启动：

```bash
docker compose up -d --build
docker compose logs -f dsh-web caddy
```

云服务器安全组和 Ubuntu 防火墙需允许 TCP 80、443 入站。Caddy 使用 ACME 为公网 IP 申请并自动续期短期 HTTPS 证书；首次申请成功后从 `https://43.138.189.204` 打开网页。微信公众号仍走 `http://43.138.189.204/wechat`。

DSH 首次启动会生成带访问令牌的 URL。用以下命令查看并在浏览器打开完整 URL：

```bash
docker compose logs dsh-web | grep 'dsh web:'
```

这个 URL 带有临时登录令牌，勿公开分享。之后在 DSH 的模型设置中检查 DeepSeek 凭据。DSH 配置和工作目录分别保存在 `dsh-data`、`dsh-workspace` Docker volume 中，容器重建后仍保留。

## 范围

- dsh-pet 显示在 DSH Web 页面内，可点击、拖动和戳一戳。
- 聊天走 DSH Web 的模型配置。当前聊天不调用 Fatfish 的天气、搜索和提醒工具。
- DSH Web 使用独立容器和用户数据，不共享 Fatfish 文件系统；聊天页面只在浏览器中显示。
- IP 证书要求 80、443 从公网可达。若 ACME 首次签发失败，先看 `caddy` 日志；不要改成公开 HTTP 登录。

## 常用运维

```bash
docker compose logs -f dsh-web
docker compose logs -f caddy
docker compose restart dsh-web
```

更新 DSH-pet 版本需修改 [Dockerfile.dsh](../Dockerfile.dsh) 中固定的 DSH 或 dsh-pet 版本后重建。删除 `dsh-data` volume 会清除 DSH 的登录凭据、模型设置和会话数据。
